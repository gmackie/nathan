06 / QUESTIONS THAT SURVIVED THE PRESENTATION

There are still
some practical matters.

What does “see everything” actually include?

The Nathan source, published price inputs, workload assumptions, cost calculations and the changes your agents propose. Credentials, signing keys and personal data should remain private. Cloudflare’s underlying platform is still Cloudflare’s; this promise covers Nathan’s code and operating model. Open source makes inspection possible. It does not establish security or production readiness by itself.

Is this ready, or does the website just look ready?

The website is ahead of the evidence. Nathan is pre-beta. Initial Worker, gateway, CLI, Studio and SDK implementations exist, but complete live protocol, installation and security acceptance gates are still pending. Evaluate it in staging and contribute. Production support is planned after a monitored pilot. Read the roadmap.

Who is in charge when something breaks?

You. Your agents can work on the MIT-licensed source, but human operators own upgrades, backups, incident response and security decisions. You control your installation, identities, keys and Cloudflare account. Cloudflare still supplies the underlying platform, sets its prices and imposes its limits. The arrangement gives you code and operational control; it does not give you Cloudflare.

Does every app need to run on Cloudflare?

Nathan itself runs on Cloudflare. Apps hosted elsewhere are intended to connect as explicitly registered OIDC clients, with browser-guided setup in the launch scope. Grafana and a reference web app are acceptance targets alongside the protected Worker. Those live installation and protocol checks remain pending. Your login authority lives in your account; the apps can live elsewhere.

What am I supposed to be able to do at launch?

A CLI installation wizard, browser-guided external OIDC app setup, protected Workers, per-app users/groups or any-signed-in-user policies, and administrator/per-app MFA. Google, GitHub, passkeys, TOTP, email/password and enterprise OIDC are in the launch scope. These are release goals, not a claim that every end-to-end flow is verified. SAML and directory sync come later.

Does the hot dog make the infrastructure free?

The hot dog has no effect on the pricing. Nathan’s MIT-licensed code has no Nathan per-user license fee. Cloudflare infrastructure, auth email and your operating effort are real costs. At 50,000 retained users, the identity-only example and Clerk Pro both model $25/month. Low usage or frequent refreshes can favor Clerk. The full report shows those cases.

Where is the sustainable part?

In paying for work that is actually done, including maintenance. Keep the core auditable, document the operating model, share improvements upstream, and fund the maintenance you rely on. Lower infrastructure costs create room in that budget. They do not maintain the software. This blueprint promises neither free support, unlimited scale nor permanent vendor prices. Contributions to code, documentation and real-world validation all count.
