Launch authentication methods are confirmed

2026-10-28 · NATH-1 · Source assessed at 90ebc43

Live acceptance targets: a protected Cloudflare Worker, externally hosted Grafana and a small reference web app. Entra ID is the first upstream enterprise provider. Pin app/runtime/library versions and verify every selected sign-in method through the supported integrations before claiming compatibility.

Support all selected methods: Google/GitHub, passkeys and TOTP, email/password, and enterprise OIDC. Operators configure the methods they use. SAML is deferred.

Shared acceptance rule: each method must preserve the same principal and application access decision. A different login method, linked account or recovery action must not create an unauthorized app grant or administrator role.

Account admission is confirmed: both invitation-only and self-service signup are supported per installation, with invitation-only as the default. First-time social and enterprise users follow the same admission setting. Accepting an invitation does not automatically grant application membership; any-signed-in-user and approved-users/groups policies remain separate.

MFA requirements are confirmed: mandatory for administrators and configurable separately for each app's end users, in either application access mode. Every enabled sign-in method follows that requirement. Passkey/TOTP enrollment alone does not prove that the current session completed MFA; missing or stale verified evidence must trigger the supported challenge journey or deny protected access.

The evidence model must verify factor composition, session binding, challenge age, passkey user verification where required, recovery and refresh behavior. Upstream sign-in success cannot silently count as MFA. Elevated AAL claims remain outside the supported launch promise until independently verified.

Enterprise boundary

Upstream enterprise OIDC authenticates users into Nathan. Downstream applications trust Nathan as their OIDC provider. Federation is distinct from SCIM provisioning and from granting membership in an app.

Membership authority is confirmed: administrators manage Nathan users and groups in Identity Studio. Approved-users/groups policies use that local membership. Directory synchronization and Entra group mapping are deferred; upstream claims and staged SCIM records cannot silently change app access.

Microsoft Entra ID is the first live acceptance target. Verify tenant/issuer/audience isolation, exact callbacks, stable principal mapping, safe account linking, credential/key rotation, missing identity claims and incomplete group claims. A successful discovery fetch is not an end-to-end acceptance test. Other providers remain unverified until tested.

SAML remains unavailable in the supported launch configuration. Verify the actual exposed routes when OIDC federation is enabled, rather than relying on a hidden admin form.

Existing implementation and gaps

Password sign-in and TOTP challenge UI exist (src/auth/ui.ts:26). Registration and recovery UI are not part of that sign-in screen. Backend email verification/reset uses a configured Resend sender and credentials (src/auth/email.ts:3); password and enterprise SSO start disabled in the deployment template (wrangler.auth.jsonc:30).

Enterprise administration currently registers OIDC providers (src/auth/admin-service.ts:105), with domain verification described in docs/setup-lifecycle.md. The SSO plugin configuration also contains SAML settings (src/auth/instance.ts:105); the OIDC-only exposure boundary must be checked before release.

Remaining choices

Confirmed revocation bound: Nathan-controlled Worker access must deny within 60 seconds of committed user blocking, app disable or removal of the last matching grant. New OIDC authorization, exchange and refresh check current policy. Grafana and reference-app local-session limits still require separate measurement.

Exact token/session lifetimes, the MFA evidence model, local group/grant schema and invitation ownership, expiry and safe redemption still need an implementation design.
