The first public release is a beta after security and end-to-end acceptance pass. Production support follows a monitored pilot. Acceptance must cover larger installations; user counts alone cannot define a traffic or reliability guarantee.

1 · PUBLIC BETA · REQUIRED GATES

Prove the complete install and access journeys

An independent operator installs into their Cloudflare account with the CLI, protects a private Worker, then connects externally hosted Grafana and a reference web app through Studio. Required sign-in methods, both app access modes, invitation-only defaults, local users/groups and administrator/per-app MFA pass real positive and negative journeys.

Verify protocol validation, origin isolation, linking/recovery, rotation, failure behavior, release integrity and the 60-second Worker revocation bound under the agreed load. Publish the supported configuration and measured limits with the versioned artifact.

2 · MONITORED PILOT · EVIDENCE TO COLLECT

Observe representative installations in operation

Agree pilot workload, observation period and exit thresholds before it starts. Track sign-in/refresh failures, latency, denied access, revocation delay, Worker/D1 resource use and operator setup issues. Exercise upgrade, rollback or forward recovery, backup restore, admin recovery and key/secret rotation.

Use the pilot to find and fix lifecycle failures. A quiet installation or elapsed observation time alone cannot establish capacity or production support.

3 · PRODUCTION SUPPORT · EXIT REVIEW

Make a supported-release decision from recorded evidence

Complete independent security review and resolve release-blocking findings. Review pilot results against the agreed limits; name support and security-update owners, disclosure channel and upgrade policy. Recheck materially changed paths at the exact release revision.

Record the deployment/artifact, environments, required health checks and evidence. All gates are currently unverified; this planning document does not authorize a deployment.

Separate short bursts test 2,000 flows and 10,000 requests/second. Registered users, in-progress sign-ins and throughput are independent dimensions; these targets are unmeasured. Confirmed launch contract

Nathan runs on Cloudflare in the operator's account. CLI initial setup and browser-guided external OIDC setup are required. Each app explicitly selects approved users/groups or any active signed-in user; missing policy and disabled apps deny. Signup supports self-service and invitations, invitation-only by default. Administrators manage Nathan users/groups; directory sync and Entra group mapping are deferred.

Support Google/GitHub, passkeys, TOTP, email/password and enterprise OIDC. Microsoft Entra ID is the first upstream enterprise acceptance provider; SAML is deferred. Admin MFA is mandatory; user MFA is set per app and requires verified session evidence. Live downstream targets are the protected Worker, Grafana and an independent reference web app.

User block, app disable and final matching-grant removal must stop newly authorized Nathan-controlled Worker requests within 60 seconds of authoritative commit. New OIDC authorization, exchange and refresh check current policy. Existing Grafana and reference-app sessions require separate token/session/logout acceptance.
