Studio, hosted pages, installer and gateway pages. The marketing site is out of scope. Absorbs NATH-26 and NATH-30 (a), (c) and (d).

Server-rendered pages with small islands

Hosted pages are rendered in the Worker. Forms post without JS. Only passkey (WebAuthn) and similar features hydrate as islands.

Spike findings (measured)

Tested locally with @cloudflare/kumo@2.19.0, React 19, @phosphor-icons/react and esbuild 0.25.

  • Server rendering works. renderToString renders Button, Input, Banner, Checkbox and Badge. Phosphor icons come out as inline SVG, so img-src 'none' stays.
  • Inline styles conflict with the CSP. Kumo writes style="" attributes, for example the Button emphasis custom properties and the visually-hidden checkbox input. Nathan's nonce-only style-src blocks those, so K0 needs a CSP-safe renderer (below).
  • Kumo ships precompiled CSS (kumo-standalone.css, Tailwind 4.1 output), so no Tailwind build step is required to start.

How a hosted page renders

Request→ Route handler (existing checks unchanged)→ renderPage(<Page/>): renderToString→ Move style="" into classes in a nonce'd <style>→ Same-origin hashed CSS and island JS, with SRI→ The same security headers as today
CSP details
  • style-src 'self' 'nonce-…'. The rendered markup has no inline style attributes, because each unique declaration becomes a generated class in the nonce'd block. A test fails the build if any style= remains.
  • script-src 'self' 'nonce-…', used only for islands. Pages without islands keep sending no script at all, including the SAML confirmation page, which never has script.
  • After hydration, React updates styles through CSSOM, which CSP allows. Islands are kept small so they don't re-render whole pages.
  • Everything else is unchanged: default-src 'none', frame-ancestors 'none', form-action 'self', base-uri 'none', Referrer-Policy: same-origin, COOP and HSTS.

Goals and non-goals

Goals

  • Every surface uses Kumo components, Kumo tokens and Phosphor icons.
  • One light and one dark theme. The NATH-30 per-app branding hook lives on Kumo tokens.
  • Accessibility at least matches today: labels, focus, keyboard, and the alert regions that carry reason codes.
  • Behavior, audit events, reason codes and headers are identical. Every existing test keeps passing.

Non-goals

  • No auth, policy or API behavior changes. Those stay in their own issues.
  • No relaxing the CSP (no 'unsafe-inline').
  • The marketing site. It keeps its own styling.
  • No new Studio features beyond parity and the branding editor.

Mitigations
  • Inline styles vs. CSP: the K0 renderer moves them into classes, and a test fails on any style=. The CSP is never relaxed.
  • Merge conflicts with NATH-24: K1 (hosted pages) goes first. K2 rebases onto NATH-24 once it merges, and Studio *-ui.ts files stay untouched until then.
  • Passkey island regression: keep the existing WebAuthn calls verbatim inside the island, plus a runtime test and a manual Safari and Chrome check before merging.
  • Server-rendered popovers and portals: base-ui dialogs and menus render client-side only. Hosted pages avoid them; Studio is an SPA.
  • Bundle size: per-component imports and one cached vendor chunk. Pages without an island ship no JS.
  • Kumo churn and supply chain: exact pins, a committed lockfile, npm ci in CI, and deliberate upgrades only.
  • Worker size limit: report the bundle size in CI and keep echarts and shiki out of the Worker.
